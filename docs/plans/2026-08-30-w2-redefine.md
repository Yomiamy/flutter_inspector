## 2. 實查證據

### 2.1 文件宣稱 vs 實況

| 文件宣稱 | 實查結果 | 判定 |
|:---|:---|:---|
| pre 端「檢查的是**字串**，不是實際能寫到哪」 | `run_pre()` 比對目標 worktree 絕對路徑，不符即 `sys.exit(2)`，**具實際阻擋力**（BUG-1 的 exit code 教訓已內化，程式碼內有註解說明） | ❌ 不成立 |
| 限制手段只是「prompt 裡的一段文字……沒有強制力」 | hook 在 `PreToolUse` 攔截，與 prompt 文字無關；另有 P-1～P-6 六道 false-positive 防護（payload 解析、工具名、worktree 判定、state 檔、branch 比對、stage 比對） | ❌ 不成立 |
| post 端「只告警不阻斷」是缺口 | 屬實，但為**刻意設計**（程式碼標記 `U-1`）：PostToolUse 時動作已完成，回捲無意義 | ⚠️ 屬實但非疏漏 |
| 「只涵蓋主 repo 與已知 worktree，寫到非 git 位置完全偵測不到」 | 屬實。`take_status()` 建立在 `git status --porcelain` 上，這是固有天花板。腳本檔頭已自行載明「屬另案」 | ✅ 成立（唯一真實缺口） |

補充實況（文件未記載）：

- `whitelist_roots()` 動態解析 git 內部目錄、`PUB_CACHE`、Flutter/Dart SDK 根（由 `which` 反解，相容 fvm）、`TMPDIR`——**禁止硬編碼標準路徑**
- `is_allowed()` 兩側都 `realpath`，防 symlink 與 `..` 繞過，並以路徑分隔符為界避免 `/x/.pub-cache-evil` 誤判命中
- `diff_entries()` 只回報 after 新增項，委派前既有的 dirty 檔不算越界（P-9）
- fail-open 設計（P-11）：hook 自身壞掉不連帶卡死 workflow
- 已有 `.claude/hooks/tests/test_delegate_cwd_logic.py`，執行結果 `OK`

### 2.2 五個候選方案的實查判定

| 候選方案 | 判定 | 依據 |
|:---|:---|:---|
| pre 端對正規化絕對路徑做強制校驗 | ✅ **已實作** | `is_allowed()` 雙側 `os.path.realpath` 比對 |
| 容器隔離 | ❌ 出局 | 對單人 Flutter package 過度工程——brainstorm 自己已如此評估過 Dagger／Container Use |
| 專用受限使用者 + 檔案系統權限 | ❌ 出局 | 需改動系統層帳號，遠超問題嚴重度 |
| 受限掛載點 | ❌ 出局 | 同上 |
| 限制寫入型委派，只允許唯讀分析 | ⏸ 保留 | 唯一完全落在專案內且確定有效，但會實質閹割 STAGE 2 委派能力 |

額外發現（文件未列）：`/usr/bin/sandbox-exec` 存在，是唯一能真正做到 fs 層限制的方案，
但 MCP server 於 `~/.claude.json` 以 `npx -y gemini-mcp-tool` 啟動、`"env": {}`——
**那是全域設定，不在本 repo 內**，且會影響所有專案而非僅此 repo。

### 2.3 實用性判準（Linus 第三條）

| 指標 | 實測值 |
|:---|:---|
| `mcp__gemini-cli__ask-gemini` 累計呼叫 | **2 次**（`~/.claude.json` skillUsage） |
| `gemini` CLI | **未安裝**（`which gemini` → not found；僅有 `agy`） |
| `cwd-violations.log` | **從未產生**（全 repo find 零命中） |

→ 此委派路徑在本專案的實際使用量趨近於零。為零使用量的路徑補強安全邊界，
複雜度與嚴重度不匹配。
